# xtpl

*Versão em português: [README.md](README.md). Essa é a principal.*

An experimental source-to-source compiler that takes a higher-level dialect of
AdvPL/TLPP and emits ordinary TLPP.

It exists to answer one question: **what modern language features could be
given to Protheus developers without changing the runtime?** The TypeScript
argument, made against AdvPL.

## What it is actually good for

Honestly: **prototyping language design**, more than writing code.

The most useful artefact in this repository is probably
[`docs/design.md`](docs/design.md) — why the language is the way it is, and
what was refused. It holds more discarded than kept, which is the point.

Some of what it found, none of which is obvious until you try to build it:

- `for each` cannot honestly borrow Harbour's spelling, because a transpiler
  must choose one lowering at compile time and Harbour's decides at runtime.
- A work-area record is not a value, so `for each oRow in rows("SA1")` is
  incoherent however natural it reads.
- `distinct` and `uniq` are genuinely different algorithms and a language
  wanting both needs both names.
- A guard that folds a statement into a code block cannot hold a loop.

If you are thinking about what AdvPL could grow into, that record may save you
some time. If you want a tool to write Protheus code with today, this is
probably not it.

## What it does

Roughly, on top of AdvPL:

| | |
|---|---|
| **Analysis** | field, type and size checking against an exported SX3; undeclared names; unopened aliases; argument counts; inconsistent returns; unused variables |
| **Scoping** | block-scoped `local` with stack lifetime, slot reuse, and escape analysis |
| **Pipelines** | `\|>` chains that fuse into a single loop, over arrays, work areas and text files |
| **Work areas** | `using alias SA1 order 1 do ... end using`, restored at every exit including early returns |
| **Sugar** | `?:`, `?.`, `?=`, string interpolation, hash literals and subscripts, postfix `if`/`while`, `defer`, `fallback` |
| **Adoption** | `--legacy` warns rather than refuses on the one thing that stops it reading an existing `.prw`: a write to an undeclared name |

See [`docs/language.md`](docs/language.md) for the reference.

## Trying it

```sh
python3 run_tests.py                     # 74 fixtures, both parsing paths
python3 xtpl_transpiler.py meu.xtpl       # writes meu.tlpp beside it
python3 xtpl_transpiler.py meu.xtpl other.tlpp
```

Python 3.10 or later. No required dependencies.

Optionally, [`rakulang`](https://github.com/ash/rakupp) — a wheel from that
project's releases, not on PyPI — enables the Raku grammar path for four
constructs. Without it the regex fallback is used, and the two are held to
producing identical output.

**Before generating anything you intend to compile**, build
`xtpl_runtime.tlpp` into a custom RPO. It defines every `__xtpl_*` function
and the `XtplQueue` class, and nothing generated will link without it.

### Checking it against a real compiler

```sh
python compile_check.py ^
  --compiler "appserver.exe -compile -files={file} -includes=C:\inc -env=MyEnvironment"
```

Transpiles every fixture with `--map`, compiles each, and reads any error back
to the `.xtpl` line that produced it. `{file}` is the only placeholder -- the
rest of the command passes through as you typed it.

### Running it

Compiling is not working. Once the files are in the RPO, AppServer calls a
function directly:

```sh
appserver.exe -env=YourEnvironment -run=u_selftest
```

`54_selftest` is the fixture built for this: it checks its own answers and
prints a total.

```
selftest: 63 ok, 0 falhas
```

### Checking the two parsing paths agree

```sh
python3 fuzz_paths.py --runs 400
```

Generates programs and diffs the grammar path against the regex one. Two bugs
came out of its first run.

### Version

`VERSION.TXT` holds the number, and `python xtpl_transpiler.py --version`
prints it. `MANIFEST.TXT` lists the release's fixtures; `run_tests.py` and
`compile_check.py` report files left over from an earlier release, which is
what unpacking over an older one leaves behind.

## Contributing

Bug reports are welcome, especially anything that fails to compile — that is
the gap the test suite cannot close.

Feature requests are a harder sell. Every construct here was judged by one
question: **what does this give an AdvPL programmer that plain AdvPL
doesn't?** Applied honestly, it removed more than it added. `docs/design.md`
records what has already been considered and rejected, and why; please read
the relevant entry before proposing something it covers.
